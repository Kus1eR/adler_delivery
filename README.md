# Доставка

Курьерская служба — мобильное приложение на Flutter + FastAPI, с веб-панелью администратора.

## Структура проекта

- `backend/` — FastAPI сервер (Python)
- `dostavka_app/` — Flutter мобильное приложение
- `frontend/` — Web Admin Panel (React + TypeScript + Vite)

## Быстрый старт

### Бэкенд

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
# Замените SECRET_KEY в .env на длинное случайное значение.
alembic upgrade head
python seed.py
uvicorn app.main:app --reload --host 0.0.0.0
```

Предпочтительные REST URL: `/api/v1/admin` и `/api/v1/courier`.
Старые `/api/admin` и `/api/courier` сохранены как deprecated-compatible aliases.

### Web Admin Panel

```bash
cd frontend
npm install
npm run dev
```

Открыть в браузере: http://localhost:5173

По умолчанию карта использует бесплатные OpenStreetMap/Leaflet и не требует ключа.
Для Yandex Maps JS API 2.1 скопируйте `frontend/.env.example` в
`frontend/.env.local`, задайте `VITE_MAP_PROVIDER=yandex` и укажите
`VITE_YANDEX_MAPS_API_KEY`. Ключ создаётся в
[Кабинете разработчика Яндекса](https://developer.tech.yandex.ru/keys/) для
JavaScript API и должен быть ограничен разрешёнными доменами. `.env.local` не
коммитится. Если ключ отсутствует или API не загрузился, панель автоматически
покажет OpenStreetMap с уведомлением.

**Технологии:** React 19, TypeScript, Vite, Tailwind CSS 4, shadcn/ui, Leaflet / Yandex Maps JS API 2.1, TanStack Query, Zustand, JWT-авторизация, WebSocket (реальное время).

### Flutter

```bash
cd dostavka_app
flutter pub get
flutter run
```

Flutter продолжает использовать `flutter_map`/OpenStreetMap и открывает адреса
во внешнем приложении или веб-версии Яндекс Карт без API-ключа. Нативный Yandex
MapKit намеренно не подключён: его следует добавлять отдельным решением после
получения мобильного API-ключа и оценки размера SDK, платформенных настроек и
условий лицензии.

Тестовые данные после `python seed.py`:

- Администратор: `admin` / `admin123`
- Курьеры: `+79001111111`, `+79002222222`, `+79003333333` / пароль `courier123`

Это публичные demo/local credentials только для seed-базы. Не используйте их в
production и смените все пароли перед размещением приложения в сети.

### Запуск всего сразу

```bash
run_all.bat
```

Запускает 3 сервиса в отдельных окнах: бэкенд, фронтенд (web admin), Flutter.
Скрипт использует существующий локальный `backend/.env`; без него запуск
останавливается с инструкцией создать файл из `backend/.env.example`.

## Возможности

- 📱 Приложение для курьеров и администраторов
- 🖥 **Web Admin Panel** — адаптивная панель администратора:
  - **Заказы** — создание, редактирование, soft-delete, отмена с причиной, поиск, серверная пагинация, фильтрация и CSV export
  - **Курьеры** — добавление курьеров, переключение статуса (онлайн/офлайн)
  - **Статистика** — сводка по заказам, курьерам, доходам
  - **Карта** — периодическое HTTP-обновление координат курьеров и заказов
  - **Администраторы** — создание и отключение дополнительных администраторов суперадминистратором
- 🌓 Светлая/тёмная тема web-панели
- 🔐 JWT-авторизация, rate limits на login, проверка активных пользователей и атомарное взятие заказа
- 🗺 Интерактивная карта (OpenStreetMap / Leaflet по умолчанию, опционально Yandex Maps JS API)
- 📦 Управление заказами с поиском и пагинацией в web и Flutter admin
- 📴 Ограниченная offline queue Flutter для безопасного повтора статусов и последней геопозиции; взятие заказа требует сети
- 🔋 Адаптивная геолокация/polling и WebSocket-уведомления уменьшают расход сети и батареи
- 📊 Статистика доставок

### Несколько заказов у курьера

Один курьер может одновременно взять несколько доступных заказов. Все они
отображаются в «Моих заказах», а статус каждого заказа меняется независимо.
Объединение заказов в маршрут и автоматическая оптимизация порядка точек пока
не реализованы.

## Перед production / будущие обновления

Текущая конфигурация предназначена для портфолио и локального запуска. Перед
production нужны отдельные инфраструктурные и продуктовые работы:

- Перейти с SQLite на PostgreSQL до масштабирования; SQLite оставить для портфолио и локальной разработки.
- Добавить Docker, `docker-compose` и воспроизводимый deployment-процесс.
- Ограничить CORS allowlist реальными production origin.
- Добавить refresh/revocation для JWT, сократить срок access token и рассмотреть httpOnly cookies для web.
- Вынести состояние WebSocket и pub/sub в Redis для работы нескольких backend worker.
- Настроить backup/restore, monitoring, Sentry и structured logs.
- Включить HTTPS и подготовить release network security config без небезопасных debug-разрешений.
- Добавить уведомления получателю, фото подтверждения доставки, ETA, маскированную связь и рейтинги.
- Использовать очередь/message broker для надёжной доставки уведомлений.
- Реализовать нативную фоновую работу на iOS; Yandex MapKit оставить опциональным после оценки SDK и лицензии.
- Добавить batching и оптимизацию маршрута для нескольких заказов.
- Пароль курьера уже реализован; OTP остаётся необязательным будущим усилением входа.
- Legacy API paths deprecated; новые клиенты должны использовать `/api/v1`.
